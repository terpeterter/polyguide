# Обоснование технологий: ИИ-ассистент для цифрового кампуса

Команда разработки · проект «ИИ-ассистент для цифрового кампуса» · Московский Политех

## 1. Что мы делаем

Чат-ассистент для первокурсника. Он отвечает на вопросы про учёбу и организационные вопросы (стипендии, медпомощь, проекты, сроки) **только по официальным документам университета**, всегда показывает источник и честно говорит «не знаю», если ответа в базе нет. Если ответа нет, он подсказывает, в какую службу обратиться.

Ключевой сценарий: студент задаёт вопрос, получает короткий ответ со ссылкой на документ. Это прямо соответствует требованию задания: интерфейс или диалог, показ источников данных и обработка недоступной информации.

## 2. Предварительный выбор технологий и почему

Выбор предварительный: мы начинаем с этих технологий и можем заменить любую из них, если прототип покажет, что она не подходит.

| Решение | Выбор | Почему |
| --- | --- | --- |
| Язык | Python | Все участники команды знают его хотя бы на базовом уровне; для работы с текстом и ИИ у него больше всего готовых инструментов |
| Интерфейс | Streamlit (предварительно) | Чат собирается быстро на том же Python, не нужно отдельно учить фронтенд; есть готовые блоки для чата, загрузки файлов, таблиц и страницы администратора |
| Поиск по документам | Поиск по ключевым словам (BM25), затем сравнение с векторным поиском | Начинаем с простого и понятного; не зависит от внешних сервисов; для десятков документов даёт хорошее качество. Векторный поиск добавим и сравним по метрике |
| Ответ модели | Языковая модель через API, ответ строится по найденным фрагментам (RAG) | Модель не выдумывает, а пересказывает найденные документы; провайдера можно менять без переписывания проекта |
| Хранение знаний | Текстовые файлы и PDF в папке проекта, индекс в JSON | Не нужна отдельная база данных; любой участник может добавить документ |
| Командная работа | GitHub, ветки и pull request | 8 человек работают параллельно и не ломают друг другу код; ключи и пароли хранятся вне репозитория |

## 3. Рассмотренные альтернативы

Если проект окажется проще или сложнее ожиданий, мы можем перейти на другой вариант. Поиск, модель и данные устроены независимо от интерфейса, поэтому переход не потребует переписывать всё.

- **Telegram-бот.** Запрещён условиями проекта.
- **Мобильное приложение.** Выглядит эффектно, но сборка и тестирование на устройствах занимают больше времени. Возможный вариант, если останется время.
- **Chainlit и Gradio.** Похожи на Streamlit. Chainlit даёт более современный вид чата, но на текущих версиях библиотек запустить его не удалось. Остаётся кандидатом.
- **FastAPI с React или HTML-страницей.** Даёт больше свободы в дизайне и более «взрослую» архитектуру, но требует больше времени и знаний фронтенда. Остаётся вариантом развития проекта.
- **Дообучение собственной модели.** Дороже и дольше; для нашей задачи подходит подход с подключением документов (RAG).
- **Low-code платформы.** Быстро, но сложнее показать собственную архитектуру и контролировать поведение.

## 4. Архитектура в одну строку

Вопрос студента → поиск по базе документов → найденные фрагменты → языковая модель формулирует ответ → пользователь видит ответ и источник.

Если подходящего фрагмента нет, ассистент не отвечает «из головы», а говорит, что не нашёл ответ, и подсказывает контакты нужной службы.

Части системы независимы: интерфейс, поиск, модель и загрузка данных можно менять по отдельности. Это позволяет работать параллельно и заменять технологии без переписывания всего.

## 5. Данные

- Источники: официальные страницы сайта mospolytech.ru и документы университета.
- Исследователи группы передают список реальных вопросов первокурсников и материалы; их формат уточняется, поэтому система принимает txt, md и pdf.
- Каждый ответ содержит ссылку на источник и дату обновления, потому что размеры выплат и сроки меняются.
- Закрытые сервисы (личный кабинет, почта) и личные данные студентов мы не используем.

## 6. Безопасность и ограничения

- Ключи доступа к модели хранятся в отдельном файле и не попадают в репозиторий.
- Доступ администратора (загрузка документов) защищён паролем; это упрощённая схема, для продакшена нужна полноценная авторизация.
- Журнал обратной связи («не помогло») не должен содержать персональных данных.
- Ассистент не заменяет официальные ответы: он направляет к документам и службам.

## 7. Как измеряем результат

Набор из 30–50 реальных вопросов с известными правильными источниками. Метрика: доля вопросов, для которых нужный документ найден. Для презентации: сравнение «было» (студент ищет сам по сайту) и «стало» (ответ с источником в чате) по критериям JTBD.
